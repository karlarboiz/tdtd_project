# GAP-002 — IDOR route enforcement

**Priority:** P0 · **Status:** In progress (Phases A–D implemented; pending final sign-off) · **Depends:** GAP-001 (schema + DAO threading) · **Unblocks:** GAP-003, GAP-032, GAP-042, MH §A4 safe hosting

**Related:** [Gap-Backlog-Doc.md](../documentation/Gap-Backlog-Doc.md) · [GAP-001.md](./GAP-001.md) · [Role-Based-Function.md](../documentation/Role-Based-Function.md) §2 · [MH-Mobile-App-Deployment.md](../must-haves/MH-Mobile-App-Deployment.md) §A4 · [ownership.ts](../../tdtd-node/src/lib/ownership.ts)

## Problem statement

GAP-001 adds `user_id` columns and threads `userId` through DAOs and most controllers. Authentication (AUTH-001) gates `/api/*`, but **cross-tenant access remains possible** when:

- Write payloads reference foreign `studentId` or `schoolYearId` without ownership validation
- Batch PDF jobs query rows by ID only (`classes WHERE id = ?`) while node sets `TDTD_REPORT_USER_ID` that batch did not read

| Layer | GAP-001 | GAP-002 |
|-------|---------|---------|
| Schema + `user_id` columns | In progress | — |
| DAO `WHERE user_id = ?` | In progress | — |
| Handlers pass `req.auth.id` | Mostly done (~49/52) | Audit + close gaps |
| Service validates foreign IDs | Partial | **Required** |
| Batch report queries scoped | Partial (reminders only) | **Required** |
| HTTP IDOR test suite | — | **Required** |

**Risk:** Until GAP-002 closes confirmed gaps, a hosted multi-teacher deployment leaks data via ID guessing (IDOR).

---

## Goal

Complete the **route and service ownership audit** so every read/write path returns only the authenticated teacher's data, with defense-in-depth in both `tdtd-node` services and `tdtd-batch` report DAOs.

**No API contract changes** — clients keep the same URLs and payloads; server rejects cross-tenant IDs with 404.

---

## Boundary with GAP-001

| GAP-001 (this epic) | GAP-002 (this epic) |
|---|---|
| Schema + migrations + backfill | Full route/controller audit |
| DAO/query signatures accept `userId` | Every handler passes `req.auth.id` |
| Services set `user_id` on create | 404 on cross-tenant ID access |
| Shared ownership helpers | Penetration-style IDOR test checklist |
| Batch reminder per-user iteration | Batch report DAO `user_id` scoping |

---

## Error contract

Follow existing `assert*Owned` helpers in [`ownership.ts`](../../tdtd-node/src/lib/ownership.ts):

| Situation | Status | Rationale |
|-----------|--------|-----------|
| Missing / invalid JWT | **401** | `authenticate` middleware |
| Cross-tenant resource ID | **404** | Avoid ID enumeration |
| Invalid payload shape | **400** | Validation errors |
| Password expired | **403** | `requireFreshPassword` (`PASSWORD_EXPIRED`) |

## Confirmed gaps

| Severity | Location | Issue | Fix |
|----------|----------|-------|-----|
| P0 | `GET /api/reports/:form` + batch | Node sets `TDTD_REPORT_USER_ID`; batch ignored it. `DepEdReportDao.getClass` had no `user_id` filter | Pre-flight `assertClassOwned` / `assertStudentOwned` in node; read env in batch; scope all report DAO queries |
| P0 | `POST /api/attendance/save` | `saveAttendance` accepted arbitrary student IDs without `assertStudentOwned` | Validate every student ID belongs to caller before writing records |
| P1 | `POST /api/deped/daily-attendance` | Class checked; student not validated | `assertStudentOwned` + verify `student.classId === payload.classId` |
| P1 | DepEd grade/archive/autofill routes | Optional `schoolYearId` not validated | `assertSchoolYearOwned` on all deped grade paths |
| P2 | `POST /api/sync/push` | Stub accepts changes without row validation | Blocked on GAP-042 |
| N/A | `/api/holidays/*` | Global `government_holidays` | Documented intentional exception |

## Code changes

### Phase A — Node service hardening

- [`attendance.service.ts`](../../tdtd-node/src/services/attendance.service.ts) — `assertStudentOwned` for all student IDs in `saveAttendance`
- [`deped.service.ts`](../../tdtd-node/src/services/deped.service.ts) — student + school-year ownership on write/read paths
- [`reports.service.ts`](../../tdtd-node/src/services/reports.service.ts) — `assertClassOwned` / `assertStudentOwned` before spawning batch

### Phase B — Batch report scoping

- [`AttendanceReportDao.java`](../../tdtd-batch/tdtd-batch-dao/src/main/java/com/tdtd/batch/dao/AttendanceReportDao.java) — `user_id` on session lookup + class list
- [`DepEdReportDao.java`](../../tdtd-batch/tdtd-batch-dao/src/main/java/com/tdtd/batch/dao/DepEdReportDao.java) — scope `getSchoolName`, `getClass`, `listStudentsByClass`
- [`AttendancePdfService.java`](../../tdtd-batch/tdtd-batch-services/src/main/java/com/tdtd/batch/service/AttendancePdfService.java) — thread `userId` through `generate()`
- [`DepEdPdfService.java`](../../tdtd-batch/tdtd-batch-services/src/main/java/com/tdtd/batch/service/DepEdPdfService.java) — read `TDTD_REPORT_USER_ID`; fail fast if missing
- [`BatchConfig.java`](../../tdtd-batch/tdtd-batch-util/src/main/java/com/tdtd/batch/util/BatchConfig.java) — parse `TDTD_REPORT_USER_ID`
- [`AttendancePdfJob.java`](../../tdtd-batch/tdtd-batch-app/src/main/java/com/tdtd/batch/job/AttendancePdfJob.java) — require `userId` env

### Phase C — Ownership helper extensions

[`ownership.ts`](../../tdtd-node/src/lib/ownership.ts):

- `assertSchoolYearOwned(db, schoolYearId, userId)` → `SchoolYearRow` or 404

### Phase D — IDOR test suite

- HTTP-level tests via `createApp` + fetch — [`idor.routes.test.ts`](../../tdtd-node/src/routes/idor.routes.test.ts)
- Extend [`ownership.isolation.test.ts`](../../tdtd-node/src/services/ownership.isolation.test.ts) for attendance save + deped paths
- Batch DAO isolation test — [`DepEdReportDaoTest.java`](../../tdtd-batch/tdtd-batch-dao/src/test/java/com/tdtd/batch/dao/DepEdReportDaoTest.java)

**Minimum scenarios:**

- User B cannot list User A's classes
- User B with User A's `classId` → 404 on class-scoped routes
- User B cannot save attendance with User A's student IDs
- User B cannot access User A's school year on grade routes
- Batch `getClass(ownedId, wrongUserId)` returns null
